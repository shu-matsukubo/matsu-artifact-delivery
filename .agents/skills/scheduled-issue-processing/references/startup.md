# 起動条件と中断判断

Codex のスケジューラ / オートメーションから同一スレッドで繰り返し実行する。スケジューラから Skill 名を直接指定して起動する。通常の Issue 対応や一般的な開発作業では使用しない。

人間が普段操作するリポジトリとは別の、スケジューラ専用 clone / 作業ディレクトリを使う。

Git・GitHub の確認は [AGENTS.md](../../../../AGENTS.md#git-と-github-の操作)に従う。

1. リポジトリの Open PR とローカルの作業状態を、同一スレッドの過去の結果と照合する。[再開判定](../../issue-development-workflow/references/resume.md)に従い、対象の作業ツリーのブランチ・ローカル HEAD・リモートブランチの先端 SHA・staged / unstaged / untracked を確認する。ブランチ名だけで通常の Issue 作業を定期処理とみなさない。
2. 由来不明の変更、競合、Git 操作中の状態や、対象の Issue・ブランチ・作業ツリーを特定できない未完了作業があれば、人間による確認が必要と報告して停止する。新規開始は clean な作業ディレクトリから行う。
3. この定期処理で作成したと一意に特定できる Open PR があり、再開判定のレビュー待ち条件を満たす場合だけ、レビュー待ちとして終了する。未反映の変更や未 Push のコミットがある場合は、差分を保全して Workflow に既存作業の再開を任せる。
4. 中断条件に該当しなければ Workflow を呼び出す。過去の会話や Memory 等は補助情報とし、GitHub とローカルの現在状態で判断する。補助情報が利用できないことだけでは停止しない。

再開・新規選定・実装・PR 作成の手順は [issue-development-workflow](../../issue-development-workflow/SKILL.md) に従う。
