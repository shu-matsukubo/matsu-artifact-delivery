# 起動条件

Codex のスケジューラ / オートメーションから同一スレッドで繰り返し実行する。スケジューラから Skill 名を直接指定して起動する。通常の Issue 対応や一般的な開発作業では使用しない。

人間が普段操作するリポジトリとは別の、スケジューラ専用 clone / 作業ディレクトリを使う。

GitHub 操作ごとに、必要な capability と権限を確認し、次の順で利用可能な手段を選ぶ。

1. GitHub Plugin を最優先にする。
2. Plugin が使えない、または必要な機能がない場合は `gh` を使う。
3. 両方が使えない、必要な権限がない、操作の成否を確認できない場合は停止し、ユーザーへエラーと不足事項を報告する。

ローカルの取得・状態確認・ステージ・コミット・Push は通常の Git CLI を使う。書き込み結果が不明な場合は現在状態を再取得して判断し、確認できなければ停止して報告する。

独自の状態ファイルやチェックポイントファイル（リポジトリ外、`.codex/runtime`、Issue 処理専用の JSON / YAML、前回ステップ番号等）は作成・永続化しない。状態管理用のラベルは追加しない。実行結果や中断内容は同一スレッドで報告する。
