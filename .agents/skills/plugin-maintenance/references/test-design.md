# テスト設計の観点

## 変更前の確認

- 変更箇所に対応する単体テストと E2E テストを特定する。
- 単体テストでロジック、境界値、入力エラー、失敗時の扱いを確認できるか調べる。
- E2E テストでコンポーネント間の接続、配布物内の参照、実際の利用経路を確認できるか調べる。
- 変更後も維持する契約と、依頼された仕様変更を分ける。

## テストが不足するとき

実装前に、維持すべき挙動と新しい要件を表す最小のテストを追加する。テストを先に実行して結果を確認する。

- バグ修正では、問題を再現する回帰テストが修正前に失敗し、修正後に成功することを確認する。
- 変更しない挙動のテストは修正前に成功し、修正後も成功することを確認する。
- 意図した仕様変更に関するテストだけを新しい期待値へ更新し、失敗を隠すためにテストを弱めない。

## 実装後の確認

変更箇所に対応する単体テストと E2E テストを選び、変更後に再実行する。MCP、配布、共通基盤に影響する場合は、[テスト・検証観点](../../../../docs/testing-review.md)と[試験と差分 CI](../../../../docs/testing.md)に従って対象を広げる。
