# 仕様の明確化

設計・タスク分解・実装へ進む前に、依頼内容、既存の仕様・資料、関係するコードを読み、求められる結果、制約、未決定の仕様を整理する。仕様の確認に必要な読み取り調査は進めてよい。

仕様上の曖昧さ、矛盾、判断待ちが残るときは、関連する論点をまとめて利用者に質問する。回答を受けたら仕様を再確認し、判断が残る場合は追加で質問する。回答が揃うまで設計、タスク分解、実装を始めず、作業中に新たな仕様上の疑問が見つかった場合は該当箇所を止めて確認する。委任先は判断待ちを親へ返し、親が利用者に確認する。

変数名、関数分割、内部実装など、仕様を変えない技術的な判断は AI が行う。仕様が明確なら質問を追加せず、通常の手順へ進む。

レビューのような読み取り作業は仕様と確認できる範囲で進めてよい。未確定の仕様に依存する結論は保留し、その論点を利用者または親へ返して確認する。
