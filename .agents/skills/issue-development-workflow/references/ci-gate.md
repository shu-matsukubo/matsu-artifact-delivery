# 必須 CI 完了ゲート

PR の作成・更新後、および既存 PR を再開して未反映変更がなく clean と判定した後に、最新 HEAD の GitHub Actions 完了と成功を確認する。未起動、チェック一覧が空、実行中、取得失敗は成功とみなさない。

## 判定

1. PR の最新 head SHA を取得し、検証・レビュー済み SHA と一致することを確認する。完了判定は[CI ゲートスクリプト](../scripts/wait-ci.ts)に委ね、同じ SHA の全 check run と Commit Status を取得して、`Quality gate` の成功を確認する。全 check は完了していなければならず、失敗・取消など成功以外の異常結果は失敗として扱う。`Unit / ...` と `E2E / ...` の `skipped` は対象外ジョブとして許容する。Plugin 経由では同じ SHA の全 Actions run と各 run の全 job を取得し、Quality gate job、各 job の完了・結果、Commit Status を照合する。取得ページ数と総件数が一致しない、または100件を超えて全件性を確認できない場合は失敗として停止する。
2. まだチェックが出ていない、または実行中なら20秒間隔で再取得し、開始から30分でタイムアウトする。API エラー、タイムアウト、取消、失敗はゲート失敗として扱う。
3. 失敗した check の Actions run とログを読み、原因を分析する。対応可能なら修正し、対象検証と親レビューを行ってから Push する。修正 Push は最大3回までとし、各 Push 後に最新 SHA を取り直して手順1からやり直す。上限到達または対応できない失敗は保全して停止し、詳細を報告する。
4. 待機中は PR の head SHA を再取得し、成功直前にも照合する。検証済み SHA と違う場合は停止し、親レビューを経て新 SHA の検証を済ませてから再実行する。
5. 全チェックが完了し、Quality gate が成功したらレビュー待ちで終了する。このゲートで人間レビューやマージは行わない。テスト削除、検査無効化、必須チェック緩和によって成功を作らない。

呼び出し例: `node .agents/skills/issue-development-workflow/scripts/wait-ci.ts <owner/repository> <PR番号> <検証済みHEAD SHA>`。各通信は10秒で打ち切り、全体期限は30分。期限超過時は最終確認した SHA とチェック状態を表示する。

権限不足、CI障害、実行不可、取得不能、タイムアウト、修正上限到達は未完了として止め、PR URL、確認 SHA、直近 CI 状態、理由と必要な対応を同一スレッドで報告する。
