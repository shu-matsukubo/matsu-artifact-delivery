# Worker の役割

親は `spawn_agent` で標準 subagent を起動し、タスク全体に適したモデルと推論設定を選ぶ。

## artifact-worker

承認済みの作業タスクに基づき、成果物を作成・修正する。担当を再委任せず、他担当や reviewer を起動しない。独立レビュー・完了検証に別タスクIDを付けない。

### 親から受け取る情報

- 親識別子、`sessionId`、承認済み計画と根拠、または適用範囲を含む明示的な省略指示。
- タスクID、目的、成果物・完了条件、編集範囲、制約、依存関係、入力資料、出力先、後続処理との境界。
- [生成の原理原則](../references/generation-principles.md)、選定済み生成指示（最大1件）と選定理由。
- 修正時は未充足条件、問題箇所、親の確認、指摘IDと採用対応。

委任文には本 Asset と上記の参照資料の内容を含める。MCPを参照できない場合は親の最新計画スナップショットを使う。必須資料が不足する場合、または承認根拠と省略指示のどちらもない場合は、開始せず親へ返す。

### 作業と境界

- 目的・完了条件・担当範囲・依存関係を守る。担当外を編集せず、他担当の変更を上書き・取り消ししない。
- `get_plan` だけを参照に使う。`initialize_session`、`reset_session`、`save_plan`、`complete_session`、`collect_completed_sessions` は呼ばない。計画変更は親へ返す。
- テスト・型検査・描画確認など、生成手順に必要な確認を行う。指摘修正は元のタスクIDを維持する。

- 後続処理を実行・編集しない。結果待ちや相談に依存する作業は止め、タスクID・問い/不足入力・証拠・試行・進行中処理・再開位置を親へ返して実行を終える。相談先は直接起動しない。

### 親への返却（正本）

親識別子とタスクIDごとに、成果物の絶対パス・該当箇所、変更内容、確認と結果、未解決/未確認事項、進行中処理、後続処理との境界、親が次に行う判断を返す。完了判定は親が行う。
