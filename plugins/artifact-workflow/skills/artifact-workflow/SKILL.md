# 成果物生成ワークフロー

ユーザーが `artifact-workflow` またはこの Plugin の利用を明示的に指定した場合にのみ適用する。通常の成果物作成依頼だけでは適用しない。

成果物の形式に依存せず、合意した計画に沿って作成を進める。このファイルをワークフローの正本とし、各工程に入るときに対応する参照資料を読む。

## 責務と適用範囲

この Plugin はデリバリーを支援するプラグイン集のうち、成果物生成フローのみを担当する。適用範囲は、今回の生成計画・承認・生成・品質確認と、完成品・検証結果の提示および親の後続処理への引き渡しまでとする。ここで本 Workflow を終了する。

生成フローと後続処理は、完成品・検証結果・引き渡し情報を接点とし、疎結合に保つ。特定の Plugin・Skill・外部サービスを必須依存にしない。ユーザーが指定した手段・引き渡し先を尊重し、指定がなければ親が依頼と利用環境に応じて選ぶ。

更新・公開・提出などの後続処理の実行・検証・結果の保証は、本 Workflow の責務外である。終了後は親が依頼全体の担当として、選択した手段の手順で続行する。本 Workflow の委任・承認・検証ルールを後続処理に持ち越さない。ユーザーの指示、既存の承認範囲、成果物と必要な情報は引き継ぐ。

親は計画前に、今回生成する成果物と後続処理の責務を分ける。後続処理の結果が必要な成果物は、その入力が得られた後に親が別の生成として扱う。依頼が後続処理だけであれば、生成タスクを作らず、本 Workflow を適用せずに親が選択した手段で進める。

親は現在のチャットを担当するエージェントのままとし、タスク分解・計画の提示・承認・委任・成果物の確認・タスクと全体の検証・完成品の提示と引き渡しを管理する。本 Workflow 内でサブエージェントを利用するのは成果物の生成・修正とそれに伴うセルフレビューのみとし、登録済みの Custom Agent `artifact-worker` を最低1人、同時に最大3人使用する。親が担当する工程にはサブエージェントを追加しない。委任時は役割と作業内容を指定し、Custom Agent の内部設定を参照・選択・上書きしない。

## タスク分解のガードレール

- **Task は作業者が成果物そのものを作成・変更する作業単位**とする。セルフレビュー、動作検証、完了条件の確認、全体検証は、作業タスクに対して行う Workflow の処理である。独立したタスクIDを付けず、修正と再確認も元のタスクIDで追跡する。
- **後続処理は本 Workflow の責務外に置く**。作業タスクと全体の完了条件は今回の生成範囲だけを対象にする。Delivery 欄は完成品の提示・引き渡しと、親が続行する依頼を記録するために使う。後続処理の実行・検証・成功条件をこの Workflow の計画に取り込まない。

## 進め方

1. **タスク分解**：[タスク分解の方針](references/task-planning.md)を読み、今回の生成範囲を定め、成果物を作るための作業だけに一意なタスクIDと、目的・成果物・確認可能な完了条件を定義する。今回の全体の完了条件と、成果物の提示・引き渡し情報は作業タスクの外に整理する。
2. **計画の提示**：[タスク計画テンプレート](assets/task-plan-template.md)を埋め、二つのガードレールを満たすことを確認してユーザーへ提示する。
3. **人間による承認**：計画を提示した段階で止まり、ユーザーの承認を待つ。修正依頼があれば計画を更新して再提示する。承認を得るまで成果物の生成へ進まない。
4. **成果物の生成**：親が[生成の方針](references/generation.md)を読み、承認済みのタスク計画と依存関係から `artifact-worker` の人数と割り当てを判断する。各担当へ計画と担当タスクIDを渡して生成を委任し、計画と同じタスクIDで成果物を対応付けさせる。
5. **セルフレビュー**：親が[セルフレビューの方針](references/self-review.md)と[成果物レビューの原理原則](references/review-principles.md)を各担当の `artifact-worker` へ渡し、生成した実物を共通原則で短く確認し、必要な修正を行うよう委任する。生成とまとめて委任してよいが、各担当が生成後にセルフレビューを行い、成果物とレビュー結果を親がタスクIDごとに受け取る。
6. **タスクの完了条件の検証**：親が[検証の方針](references/verification.md)を読み、返された成果物の実物を確認して、タスクIDごとに承認された完了条件と比較する。未充足の条件があれば、同じタスクIDで `artifact-worker` へ修正と必要なセルフレビューを依頼し、親が実物を再検証する。条件を満たしたタスクを完了とする。4〜6は各作業タスクを消化する処理であり、工程ごとの作業タスクを追加しない。
7. **全体検証**：今回の生成計画の全作業タスク完了後、親が同じ[検証の方針](references/verification.md)に従い、その成果物を全体の完了条件と照合する。問題は該当する元のタスクIDへ戻して修正・再検証し、全体の条件も満たした時点で今回の成果物完成とする。
8. **成果物の提示・引き渡しとフロー終了**：親が[引き渡しの方針](references/delivery.md)を読み、完成品と検証結果を提示するか、親の後続処理へ引き継いで本 Workflow を終了する。依頼された後続処理があれば、親はそのまま選択した手段の手順で続行する。

## 承認と完了のルール

- 原則は計画提示後の明示的な承認とする。すでに同じ計画への承認を得ている場合は、再度の承認を求めない。
- ユーザーが今回の作業について承認手続きの省略を明示した場合に限り、その指示と適用範囲を計画に記録して進める。通常の作成依頼や無応答を、計画への承認や省略の指示とみなさない。
- 作業範囲・目的・成果物・完了条件の変更が必要になったら、変更後の計画を提示して承認を得る。承認済みの範囲内での修正に、追加の承認は不要。
- 計画の提示・変更と人間承認の管理は親が行う。`artifact-worker` から計画変更の必要性が報告された場合も、この承認ルールを適用してから該当作業を再委任する。
- `artifact-worker` が利用できない場合は生成を開始せず、親が役割の登録・利用に必要な対応をユーザーへ伝える。
- セルフレビューと完了条件の検証は別工程とする。未充足または確認不能の条件が残る場合は完了扱いにせず、該当タスクIDと不足している情報・必要な対応をユーザーへ伝える。
- 今回の生成フローの完了と、依頼全体の完了を区別する。後続処理の成否や結果待ちを本 Workflow の完了条件にせず、終了済みの生成計画を自動的に再開しない。後続の依頼を省略したり、本 Workflow の完了だけで依頼全体が完了したと報告したりしない。
