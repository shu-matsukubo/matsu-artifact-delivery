# 成果物作成ワークフロー

ユーザーが `artifact-workflow` またはこの Plugin の利用を明示的に指定した場合にのみ適用する。通常の成果物作成依頼だけでは適用しない。

成果物の形式に依存せず、合意した計画に沿って作成を進める。このファイルをワークフローの正本とし、各工程に入るときに対応する参照資料を読む。

親は現在のチャットを担当するエージェントのままとし、タスク分解・計画の提示・承認・委任・成果物の確認・完了条件の検証・最終提示を管理する。サブエージェントを利用するのは成果物の生成・修正とそれに伴うセルフレビューのみとし、登録済みの Custom Agent `artifact-worker` を最低1人、同時に最大3人使用する。親が担当する工程にはサブエージェントを追加しない。委任時は役割と作業内容を指定し、Custom Agent の内部設定を参照・選択・上書きしない。

## 進め方

1. **タスク分解**：[タスク分解の方針](references/task-planning.md)を読み、依頼を必要な作業へ分解する。一意なタスクIDと、目的・成果物・確認可能な完了条件を定義する。
2. **計画の提示**：[タスク計画テンプレート](assets/task-plan-template.md)を埋めてユーザーへ提示する。
3. **人間による承認**：計画を提示した段階で止まり、ユーザーの承認を待つ。修正依頼があれば計画を更新して再提示する。承認を得るまで成果物の生成へ進まない。
4. **成果物の生成**：親が[生成の方針](references/generation.md)を読み、承認済みのタスク計画と依存関係から `artifact-worker` の人数と割り当てを判断する。各担当へ計画と担当タスクIDを渡して生成を委任し、計画と同じタスクIDで成果物を対応付けさせる。
5. **セルフレビュー**：親が[セルフレビューの方針](references/self-review.md)を各担当の `artifact-worker` へ渡し、それぞれが生成した成果物そのものの確認と必要な修正を委任する。生成とまとめて委任してよいが、各担当が生成後にセルフレビューを行い、成果物とレビュー結果を親がタスクIDごとに受け取る。
6. **完了条件の検証**：親が[検証の方針](references/verification.md)を読み、返された成果物の実物を確認して、タスクIDごとに承認された完了条件と比較する。未充足の条件があれば、同じタスクIDで `artifact-worker` へ修正と必要なセルフレビューを依頼し、親が実物を再検証する。
7. **成果物の提示**：親がすべての完了条件を満たすことを確認したら、完成した成果物またはその参照先と、タスクIDごとの検証結果をユーザーへ簡潔に提示する。

## 承認と完了のルール

- 原則は計画提示後の明示的な承認とする。すでに同じ計画への承認を得ている場合は、再度の承認を求めない。
- ユーザーが今回の作業について承認手続きの省略を明示した場合に限り、その指示と適用範囲を計画に記録して進める。通常の作成依頼や無応答を、計画への承認や省略の指示とみなさない。
- 作業範囲・目的・成果物・完了条件の変更が必要になったら、変更後の計画を提示して承認を得る。承認済みの範囲内での修正に、追加の承認は不要。
- 計画の提示・変更と人間承認の管理は親が行う。`artifact-worker` から計画変更の必要性が報告された場合も、この承認ルールを適用してから該当作業を再委任する。
- `artifact-worker` が利用できない場合は生成を開始せず、親が役割の登録・利用に必要な対応をユーザーへ伝える。
- セルフレビューと完了条件の検証は別工程とする。未充足または確認不能の条件が残る場合は完了扱いにせず、該当タスクIDと不足している情報・必要な対応をユーザーへ伝える。
