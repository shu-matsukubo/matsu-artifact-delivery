# 成果物生成の方針

親が承認されたタスク計画に従って成果物の生成を `artifact-worker` へ委任する。承認の扱いは親が [SKILL.md](../SKILL.md) に従って管理する。

委任するタスクは今回の生成範囲の成果物を作成・変更する作業に限る。セルフレビューは担当タスクを処理する指示として添え、専用のタスクIDを作らない。検証・完了確認・引き渡しや、後続処理の実行が計画に混ざっていたら、親が計画を整理してから該当作業を委任する。

## 人数と担当の判断

- 親が承認済みのタスク計画と依存関係をもとに、1〜3人の `artifact-worker` へ担当を割り当てる。相互に独立して進められるタスクが複数あり、並列化の効果がある場合に複数人を使う。依存関係がある場合や並列化のメリットが小さい場合は、1人で順次実行する。
- 生成・修正とそれに伴うセルフレビューを含め、同時に実行する `artifact-worker` は最大3人とする。追加の担当作業は、空いた担当へ順次割り当てる。
- 相談を併用する場合は、委任前に[相談用の実行枠](escalation.md#相談用の同時起動枠)を確認する。相談役はワーカー人数とは別に管理するが、client の実行枠が共通なら1枠を予約し、ワーカー人数を調整する。1枠しかない場合や全枠が使用中の場合は、同資料の返却・枠解放・再開の手順で交代する。
- 各担当のタスクID・成果物・編集範囲・出力先を明確にし、同じファイルや共有資源への編集が競合する作業を同時に割り当てない。依存する後続タスクは、親が先行成果物とセルフレビュー結果を受け取り、依存条件を確認してから委任する。
- 共通部分の修正や成果物の統合が必要な場合も、承認済みのタスクIDと範囲を明示して、1人の `artifact-worker` へ生成・修正とセルフレビューを順次委任する。
- 人数や担当の割り当ては親による実行上の判断とし、タスクID・完了条件・承認範囲は維持する。承認済みの範囲内での割り当て変更に追加の承認は不要とし、計画自体の変更が必要な場合は既存の承認ルールに従う。

## 委任時に渡す情報

- 承認済みの計画と担当タスクID。各タスクの目的・成果物・完了条件、作業範囲・制約・依存関係を含める。
- 担当する成果物の編集範囲と出力先。並列実行する場合は他の担当範囲も伝え、互いの変更を上書き・取り消ししないようにする。
- 計画への承認の根拠、またはユーザーが明示した承認手続き省略の指示と適用範囲。
- 作業に必要な入力資料・既存の成果物・出力先と、本資料、[セルフレビューの方針](self-review.md)、[成果物レビューの原理原則](review-principles.md)。参照先を読める状態で渡し、共有できない場合は必要な内容を委任文に含める。
- 修正依頼の場合は、同じタスクIDに未充足の条件・問題箇所・親の確認結果を対応付ける。
- 今回生成する成果物と、親へ返却する位置。同じ依頼に含まれる後続処理の作業領域・実行は担当外であることを伝える。
- 相談が必要な場合は、担当タスクID・問い・証拠・試した方法と再開情報を親へ返すこと。相談 Skill や相談役を直接起動せず、相談に依存する作業を止めて返却し、その実行を終えること。親は返却をタスク完了とせず、必要な枠の解放と再開を管理する。

登録済みの Custom Agent `artifact-worker` を指定して委任する。親は承認の扱いを確認してから渡し、計画変更・人間承認・タスクと全体の検証・完成品の提示と引き渡しを自ら管理する。この委任ルールは本 Workflow 内だけに適用する。

## artifact-worker が行う生成

- 作業対象をタスクIDで明確にする。成果物の参照先や該当部分とIDの対応を、後工程から確認できるようにする。成果物の本文にIDを埋め込む必要はない。
- 成果物の種類と利用環境に適した方法で作業する。特定のプログラミング言語、フレームワーク、ドキュメント形式を必須にしない。
- 作業中も目的と完了条件を参照し、必要な内容や制約から外れないようにする。依頼にない機能や内容を追加するなど、不要な作業や独断でのスコープ拡張を避ける。
- 割り当てられた担当範囲内で複数タスクをまとめて進めたり、行き来したりしてよい。依存関係を守り、タスクIDと成果物の対応を維持する。担当外の修正や他の担当との調整が必要な場合は親へ返す。
- 計画の変更が必要になった場合は、変更理由と影響するタスクIDを親へ返し、該当作業を止める。親が計画変更と承認の扱いを管理し、再委任してから作業を進める。
- 生成に利用する Skill は、今回の生成範囲と委任された担当で実行できるものを使い、その生成手順に従う。後続処理の実行や、その担当側で行う作成・編集が必要と分かった場合は、該当箇所と必要な情報を親へ返す。生成という名目で後続処理の担当範囲を編集したり、後続処理を呼び出したりしない。
- 後続処理の結果がないと完成できない作業が渡された場合は、不足する入力と該当タスクIDを親へ返す。結果を推測して完成扱いにせず、親が生成範囲を整理する。

作成後は、実際の成果物を参照できる状態で各担当の `artifact-worker` がセルフレビューへ進む。親は担当とタスクIDの対応を保って成果物とレビュー結果を受け取り、最終的な成果物の実物を確認する検証工程で完了を判断する。検証後の修正依頼にも、本資料の人数・担当範囲・依存関係のルールを適用する。
