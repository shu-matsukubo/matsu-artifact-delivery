# セルフレビューの方針

セルフレビューは、各担当の `artifact-worker` が**作成した成果物そのものを共通原則で短く見直し、問題を修正する工程**である。要求への適合も作成者として見直すが、完了条件ごとの照合と最終的な完了判定は、[独立レビュー](independent-review.md)を経て、親が[検証工程](verification.md)で実物を確認して行う。

今回の生成範囲の各作業タスクを処理するフローの一部として実施し、セルフレビュー専用のタスクは作らない。確認結果・修正・再確認は、作成を担当した元のタスクIDに対応付ける。複数タスクをまとめて確認する場合も同じ対応を保つ。後続処理の実行や、その結果の検証はセルフレビューの対象にしない。

## 確認する観点

[成果物レビューの原理原則](review-principles.md)を読み、5原則に沿って確認する。原則の定義はこの共通資料を正本とし、担当や成果物種別ごとに複製しない。

セルフレビューでは共通原則の確認に絞り、分野固有の網羅的な監査や専門チェックリストは追加しない。既知の問題は原則に照らして修正し、専門知識や資料が足りず判断できない点は未確認として親へ返す。生成手順で必要なテスト・描画確認や、承認された完了条件の検証は、それぞれの工程で引き続き行う。

## 進め方

1. 担当タスクの目的・要求・制約と、レビューする実物・関連部分を確認する。
2. 実物を読み、見る、動かすなど、各原則を判断できる方法で短く確認する。同じ実物・状態について生成中に得た確認結果は再利用してよい。確認範囲を超えた品質は保証しない。
3. 問題が見つかったら、承認済みの担当範囲内で修正する。修正箇所と影響部分を関係する原則で再確認し、影響しない確認は繰り返さない。
4. 担当外・計画変更が必要な問題や、情報・手段が足りず進められない点は親へ返す。理由なく同じ修正・確認を繰り返したり、完了条件を緩めたりしない。

問題の列挙だけで終えず、担当範囲内で対応可能な問題を修正・再確認したら親へ返し、独立レビューへ進む。未解決や未確認がある場合は、その状態を明示して返し、問題なし・完了とは扱わない。作業者からレビュワーや相談役を直接呼ばない。

## 親へ返す情報

タスクIDごとに次を簡潔に返す。5原則それぞれの定型報告や、別のレビュー報告書は必須にしない。

- 成果物の実物、または親がアクセスできる参照先と該当部分。ファイルの参照先は絶対パスで示す。
- 確認した原則・範囲・方法・結果と、重要な修正点。問題がなければ、共通原則を確認した旨と実物を確認した範囲・方法・結果をまとめてよい。
- 未解決の問題・確認できなかった点と必要な対応。該当しなければその旨を示す。問題がある場合は、該当箇所・関係する原則や要求・問題の内容と利用への影響・確認根拠を添える。

セルフレビューで問題が見つからなかったことだけで、タスクの完了条件を満たしたと判断しない。親がレビュー後の実物を対象に、別途検証する。

## 独立レビューとの分担

セルフレビュー・独立レビュー・親による検証を標準工程として実行する。独立レビューがあっても、作業者は自身で確認・修正できる問題を丸投げしない。

| 工程 | 観点と責務 |
| --- | --- |
| セルフレビュー | 作成者が共通原則を短く確認し、担当範囲内の問題を修正する。 |
| 独立レビュー | 生成担当と別の `artifact-reviewer` が同じ共通原則と、親が選んだ0〜3個の特化観点で実物を確認し、指摘を親へ返す。 |
| 検証 | 親が実物を承認済みのタスク・全体の完了条件と照合し、完了を判定する。 |

独立レビューの入力・返却契約・修正後の再レビューは[独立レビューの方針](independent-review.md)に従う。親が指摘を元のタスクIDで修正担当へ戻し、セルフレビュー・独立再レビュー・検証へつなぐ。独立レビューはセルフレビューや親の完了判定を置き換えない。
