# 成果物の引き渡しとフロー終了（Delivery）

本 Workflow の Delivery は、生成・検証を終えた完成品と必要な情報を提示するか、親の後続処理へ引き継いで、成果物生成フローを終了する境界を指す。作業タスクではなく、タスクIDを付けない。後続 Plugin の作業を実行・検証するフェーズは本 Workflow に設けない。

## 引き渡す情報

親が後続の依頼を続行できるよう、次を参照できる状態で引き継ぐ。生成だけの依頼なら、完成品と検証結果を利用者へ提示して終了する。

- 完成した成果物、またはアクセスできる参照先。ファイルの場合は絶対パスを示す。
- 今回の生成範囲・変更内容、タスクと全体の検証結果、確認した範囲と制約。
- ユーザーが依頼した後続処理と、指定された担当 Plugin・Skill・引き渡し先があればその情報。
- 既存のユーザー指示と承認範囲、後続処理へ渡す必要がある既知の条件や不足情報。
- 後続処理の結果が得られた後に行う依頼があれば、その内容と必要な入力。

これらを計画の Delivery 欄と完成時の引き渡し情報に記載する。後続処理の実行手順・検証条件・成功判定はここで定義しない。

## フロー終了後の責務

完成品と検証結果の提示・引き継ぎが済んだ時点で、本 Workflow のルール適用を終了する。同じ親エージェントがそのまま依頼全体を担当し、依頼された後続処理を担当 Plugin・Skill の手順で進める。この境界だけを理由にユーザーへの完了応答で作業を止めたり、再承認を求めたりしない。既存のユーザー指示と承認範囲を引き継ぎ、必要な追加確認は担当 Plugin の手順と実際の不足情報に基づいて判断する。

例えばアプリの生成後に Sites で更新・公開する依頼では、ここでアプリ成果物と検証結果を引き渡す。その後の Sites 側の作成・編集・更新・公開・検証は親が Sites の責務として扱う。GitHub 操作 Skill での PR 作成なども同じ境界で扱う。本 Workflow は後続処理の担当方法や検証を管理せず、委任・承認・検証ルールを持ち越さない。

## 後続の結果が必要な依頼

公開時に確定する URL を使う資料などは、今回の生成計画の完了待ちにしない。親が生成フロー終了後に担当 Plugin の処理を行い、必要な結果を得た後に別の生成として扱う。必要なら本 Skill を改めて適用し、その入力と生成範囲に対する計画・承認・生成・検証を行う。結果を待つための先行 Delivery や、終了済み計画を自動再開する仕組みは設けない。

本 Workflow の完了は依頼全体の完了を意味しない。後続処理の失敗や不足情報の扱い、後続処理中に必要になった修正・検証は、親がその担当 Plugin の責務として管理する。本 Workflow の完了だけで、依頼された後続処理や残りの成果物まで完了したと報告しない。
