# 成果物の引き渡しとフロー終了（Delivery）

本 Workflow の Delivery は、生成・検証を終えた完成品と必要な情報を提示するか、親の後続処理へ引き継いで、成果物生成フローを終了する境界を指す。作業タスクではなく、タスクIDを付けない。後続処理を実行・検証するフェーズは本 Workflow に設けない。

生成側が扱うのは、成果物の形式や必要な入力など、受け渡しに関わる条件までとする。特定のサービスの内部構造・操作手順や、担当側の実行・検証方法は取り込まない。

## 引き渡す情報

親が後続の依頼を続行できるよう、次を参照できる状態で引き継ぐ。生成だけの依頼なら、完成品と検証結果を利用者へ提示して終了する。

- 完成した成果物、またはアクセスできる参照先。ファイルの場合は絶対パスを示す。
- 今回の生成範囲・変更内容、セルフレビュー・独立レビュー・タスクと全体の検証結果、確認した範囲と制約。独立レビューの対象の版・選んだ特化観点・指摘の採否と対応・未確認事項も引き継ぐ。
- ユーザーが依頼した後続処理と、指定された手段・引き渡し先があればその情報。
- 既存のユーザー指示と承認範囲、後続処理へ渡す必要がある既知の条件や不足情報。
- 相談を利用した場合は、助言と検証の履歴、未解決の条件、未完了の相談の実行ID・状態。回数上限は後続処理へ持ち越さず、実行状態の回収責任は親へ引き継ぐ。
- 後続処理の結果が得られた後に行う依頼があれば、その内容と必要な入力。

これらを計画の Delivery 欄と完成時の引き渡し情報に記載する。後続処理の実行手順・検証条件・成功判定はここで定義しない。

全タスクと全体検証が完了し、完成品・検証結果・必要な情報を提示または引き渡したら、親が最新の `revision` で `complete_session` を呼び、完了記録の成功を確認する。完了記録後のJSONは読み取りだけを許可し、同じ保存先で次に新しい生成フローが始まると削除される。引き渡し先がJSONを読み直さなくても続行できるよう、必要な情報は先に渡す。操作は[タスク計画の一時保持](task-memory.md)を参照する。

後日の修正は、JSONが削除済みでも残っていても新しい修正タスクとして計画する。親が現在の成果物と修正要求を確認し、新しいフローの初期化・計画・承認から進める。JSONを長期保存先や別チャットへの引き継ぎ機能として扱わない。

## フロー終了後の責務

完成品と検証結果の提示・引き継ぎと完了記録が済んだ時点で、本 Workflow のルール適用を終了する。同じ親エージェントがそのまま依頼全体を担当し、依頼された後続処理を選択した手段の手順で進める。この境界だけを理由にユーザーへの完了応答で作業を止めたり、再承認を求めたりしない。既存のユーザー指示と承認範囲を引き継ぎ、必要な追加確認は選択した手段の手順と実際の不足情報に基づいて判断する。

後続処理の実行方法・検証・成功条件は担当側の責務とする。本 Workflow の委任・承認・検証ルールを持ち越さず、選択した手段に応じた進め方を尊重する。

## 後続の結果が必要な依頼

後続処理の結果を使う成果物は、今回の生成計画の完了待ちにしない。親が生成フロー終了後に後続処理を行い、必要な結果を得た後に別の生成として扱う。必要なら本 Skill を改めて適用し、その入力と生成範囲に対する計画・承認・生成・検証を行う。結果を待つための先行 Delivery や、終了済み計画を自動再開する仕組みは設けない。

本 Workflow の完了は依頼全体の完了を意味しない。後続処理の失敗や不足情報の扱い、後続処理中に必要になった修正・検証は、親が後続処理の担当側の責務として管理する。本 Workflow の完了だけで、依頼された後続処理や残りの成果物まで完了したと報告しない。
