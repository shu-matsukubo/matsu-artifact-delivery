# 成果物生成の原理原則

成果物の形式や選択した生成拡張に依存しない、共通の作り方の判断基準をここに定める。親と `artifact-worker` は、承認済みの計画をもとに本資料を適用する。成果物の品質評価と完了判定は生成方針の責務ではなく、後続するセルフレビュー・独立レビュー・親の検証で行う。

## 1. 合意した目的から作る

承認済み計画の要求・要件・成果物・完了条件・制約を生成の根拠とする。曖昧さを独断で解釈して目的や範囲を変えず、完了に必要な内容を作る。計画の変更が必要なら作業を止め、理由と影響するタスクを親へ返す。

## 2. 入力と既存状態を尊重する

渡された資料・既存成果物・プロジェクト設定を作業前に確認し、そこに示された前提や既存の構造・手順に沿って作る。既存の成果物や他担当の変更を不用意に置き換えず、担当範囲を越える変更が必要なら親に相談する。入力にない事実や結果を作り出さない。

## 3. 目的に必要な方法を選ぶ

成果物の用途・形式と利用環境に合う方法を選ぶ。特定の言語・技術・表現を一律に要求せず、既存の仕組みを活かして、目的達成に必要な内容を必要な範囲で作る。依頼されていない機能・成果物・抽象化を追加しない。

## 4. 根拠と不確実さを保つ

入力資料や確認済みの情報に基づいて生成し、重要な判断の根拠を追えるようにする。前提・未確定事項・不足情報を確定事項のように扱わない。情報不足で進められない、または判断が計画の承認範囲に影響する場合は、未解決事項と必要な判断を親へ返す。

## 5. 作業を成果物へ対応付ける

作成・変更した成果物と承認済みタスクIDの対応を保ち、完了条件に必要な内容を成果物上で特定できるようにする。複数の担当や成果物がある場合も依存関係と担当境界を守り、統合や担当外の変更が必要なら親の調整を待つ。

これらは生成時の判断基準であり、生成後のレビュー用チェックリストではない。成果物を原則ごとに採点したり、同じ品質確認を重ねたりせず、問題の確認・修正・完了判定は後続工程の方針に従う。
