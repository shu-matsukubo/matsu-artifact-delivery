# 成果物レビューの原理原則

成果物の形式やレビュー担当に依存しない、共通の判断基準をここにまとめる。セルフレビューと、将来追加するレビュー専用エージェントは、同じ原則を参照する。レビューの進め方や完了判定は各工程の責務とする。

## 5つの原理原則

| 原理原則 | 短く確かめる問い | 問題を見つける手掛かりの例 |
| --- | --- | --- |
| **要求適合** | 合意した目的・要求・制約に過不足なく応えているか。依頼された内容が成果物のどこにあるか説明できるか。 | 必要な内容や機能の欠落、制約違反、目的達成に不要な機能・説明の追加。 |
| **統一性** | 同じ意味や役割のものを、同じルールで表現・扱っているか。 | 用語・命名・単位・フォーマットの揺れ、同じ役割の見出し・操作・レイアウトの不一致、成果物内や関連部分との矛盾。 |
| **構造化・単純性** | 役割ごとの責務と関係が明確で、必要十分な構成になっているか。 | 一つの章や部品への無関係な責務の混在、同じ情報・処理の重複管理、追いにくい依存関係、不要な分割・抽象化・設定。 |
| **利用しやすさ・破綻のなさ** | 想定する利用者が目的・内容・使い方を理解でき、用途に必要な読み取りや操作が成立するか。 | 意味が伝わらない説明や導線、読めない表示やはみ出し、参照切れ、機能しない要素、今回の用途に関係する初期・空・エラー状態での破綻。 |
| **確認の裏付け** | 内容の正しさや「問題なし」という判断に、入力資料・成果物の実物・実際の確認結果による裏付けがあるか。推測や未確認と区別できているか。 | 入力と異なる数値や事実、根拠のない断定、変更の影響を受けた箇所への古い確認結果の流用、読んだだけの操作を「動作確認済み」とする報告。 |

5原則すべてに目を通し、問いや手掛かりは成果物の性質と今回の範囲に合わせて使う。例を網羅するための確認や、原則ごとの採点・チェック表の記入は求めない。

役割や用途の違いに理由がある表現差は許容する。要求を満たすために必要な補完や構成も認め、統一・単純化だけを目的に意味のある違いや責務の境界を消さない。

## 固有観点との境界

共通原則は「何を良い状態とするか」を示す。成果物種別や分野の固有知識は、その状態を詳しく判定するための別の観点として扱う。たとえば「数値や判断に裏付けがあるか」は共通原則、特定業務の計算規則の妥当性は固有観点である。

将来、固有観点を整備する場合は、対象・適用条件・必要な知識や参照資料を別資料に置き、この共通原則に種別ごとのチェック項目を積み増さない。固有観点に基づく問題も、影響する要求や原則と結び付けて説明する。
