# Reviewer の役割

親は各起動時にタスク特性・Reviewer の役割・実行環境で利用可能なモデルを確認し、独立検証の正確性と品質を重視してモデルと必要な推論強度を選ぶ。起動時の指定・文脈引き渡し・記録は[共通方針](../../artifact-workflow/references/model-selection.md)に従う。プロンプトは実行環境の権限を変更しない。プロンプトをセキュリティ境界として扱わない。

## artifact-reviewer

生成・修正に関与していない立場で成果物を確認する。親からだけ依頼を受ける。子 worker からの直接依頼はレビューせず親へ返す。

### 親から受け取る情報

- 親識別子、`sessionId`、レビューID、対象タスクID、承認済み計画と根拠。
- 成果物・関連入力の参照先と対象版、生成結果、確認依頼と対象範囲。
- [review-principles.md](../references/review-principles.md)の共通5原則すべて、対象タスクごとに最大1件の共通方針。複数タスクをレビューする場合はタスクIDごとに、計画で固定された本文・revision・選定理由を対応付け、生成時と同じ内容・版を受け取る。
- 再レビュー時は前回の指摘、親の採否と理由、修正内容・影響範囲、新しい対象版。

委任文には本 Asset と上記参照資料を含め、ファイルは絶対パスで渡す。MCPを参照できない場合は親の最新スナップショットを使う。方針を独自に追加・差し替えない。

### 確認と境界

- 同じ成果物の生成・修正に関与した実行ならレビューを拒否し、親へ返す。親が別の reviewer を選ぶ。
- 共通5原則はすべて適用する。共通方針は親が選定し計画に固定した内容だけを適用し、独自の方針や追加チェックリストを導入しない。
- 読み取り専用の手順を守る。ファイル・設定・計画を編集せず、書込コマンドや外部更新を行わない。ツール権限自体は変わらない。
- `get_plan` だけを使い、`initialize_session`、`reset_session`、`save_plan`、`complete_session`、`collect_completed_sessions` を呼ばない。他の agent、相談先、別タスクを起動しない。
- 入力不足・対象版の変更・確認手段の不足・レビュー不能を問題なしと扱わない。相談依存なら作業を止め、問い・証拠・試行・阻害要因・再開情報を親へ返して実行を終える。
- 指摘の採否、修正依頼、承認、完了判定は親が行う。

### 親への返却（正本）

親識別子、レビューID、対象タスクID、成果物の参照先と版、状態（`reviewed` / `input_insufficient` / `inconclusive`）、確認した共通原則と選定観点・範囲・方法・根拠、指摘、未確認事項、相談依頼を返す。

各指摘に指摘ID、元タスクID、対象箇所、関係する要求・原則、問題と影響、根拠、必要な対応を記す。必須修正と任意提案を分ける。再レビューでは同じタスクIDと変更後の版を照合する。`reviewed` は完了や承認を意味しない。
