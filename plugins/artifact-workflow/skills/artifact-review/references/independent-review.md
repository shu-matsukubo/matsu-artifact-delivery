# 独立レビュー

親は成果物を作成・修正していない標準 subagent 1人へレビューを委任し、親自身が指摘の採否と完了判定を管理する。起動時は [Reviewer の役割](../assets/reviewer.md)と[共通のモデル選定・起動方針](../../artifact-workflow/references/model-selection.md)に従い、独立検証の正確性・品質を重視して利用可能なモデルと必要な推論強度を選ぶ。レビューは生成後、親の検証前に行う。

## 準備と版固定

- 親は承認済み計画の最新スナップショットからタスクID・完了条件を取り出し、生成物と対応付ける。
- レビューIDを付け、成果物・関連入力・依存物の対象版を特定する。Git 管理下では commit とレビュー対象範囲の staged / unstaged / untracked の開始状態を記録し、対象ファイルのパスと SHA-256、保存時点を記録する。Git 管理外では対象作業領域内のファイル一覧と各 SHA-256、保存時点を記録する。レビュー範囲外の既存変更はこの照合に混ぜない。
- レビュー中の対象版は変更しない。レビュー前後に対象範囲のファイル一覧・追加・削除・各 SHA-256 を照合する。Git 管理下では staged / unstaged / untracked の開始状態からの増分も照合する。レビュー前からある変更は基準状態として区別する。レビュー中に対象が変わった場合は結果を破棄して最新版を固定し直し、再レビューする。これらは変更を事後に検知する照合であり、書き込みを防ぐ権限の保証ではない。変更の有無を検証できない場合も成功扱いしない。
- レビュワーは生成・修正を担当した実行から分離する。生成担当をそのままレビュワーへ切り替えない。同時に複数 reviewer を起動しない。
- reviewer の入力・返却項目は [reviewer.md](../assets/reviewer.md) を唯一の正本とし、委任文にその役割指示と以下の参照を含める。

## 観点の選定

- 親は承認済み計画の各タスクに固定された共通方針0〜1件を同じ本文・revisionで使う。これは生成では実装指示、レビューでは遵守確認となる。同じ成果物について独立 reviewer が別方針を選び直さない。
- 共通の[5原則](review-principles.md)は常にすべて適用する。計画で「該当なし」とされた場合はその理由を記録する。
- 計画の固定内容が欠ける、または対象 revision と一致しない場合は不一致を親へ返し、最新登録を代用しない。
- 方針の依存先・確認コマンド・注意を成果物とタスクに照らして確認する。MCP は依存先やコマンドを実行しない。レビューで必要な実行確認ができなければ、未確認として親へ返す。
- MCP 接続失敗や不正データを適合0件と扱わず、共通5原則を適用して失敗理由を利用者へ伝える。必須条件を満たせない場合は成功扱いしない。
- 適用条件は [登録指示の実行境界](../../artifact-workflow/references/execution-boundaries.md)に従う。依存不足で必須完了条件を満たせない場合は成功扱いしない。親は承認済み範囲内の選定に追加承認を求めない。
- 選定は親が計画時に管理し、reviewer は受け取った固定方針だけを適用する。該当なしの場合はその理由を確認記録に含める。

## 実行

- `spawn_agent` で生成・修正担当とは別の標準 subagent を起動し、reviewer.md、共通5原則、親が選んだ特化指示だけを適用させる。`artifact-reviewer` は役割テンプレート名として扱い、Custom Agent の事前登録は要求しない。
- 親と subagent の権限は実行環境に従う。利用可能なら実行環境側で読み取り専用にする。子専用の読み取り専用 Sandbox を設定できないことや、親が書き込み可能なことだけを理由にレビューを保留しない。通常のレビューでは編集・書き込みコマンド・外部更新・再委任をしないよう指示し、プロンプトが権限を制限しないことを認識して対象版の事後照合で変更を検知する。
- 利用者または上位要件が Sandbox 等による技術的な読み取り専用の強制を明示的に必須としている場合は、その条件を満たす実行環境だけを使う。設定できなければ通常レビューに切り替えず、未実施の理由を親へ返す。標準 subagent を起動できない、必要な入力を渡せない、または対象版を照合できない場合もレビューを保留し、その理由を報告する。
- reviewer は MCP の `get_plan` だけを参照し、生成・修正、計画更新、他エージェント起動、相談起動をしない。
- レビュー中または前後照合で対象の変更を検出したら旧版への結果を破棄し、新しい版を特定して再レビューする。

## 返却・修正・再レビュー

- `reviewed`、`input_insufficient`、`inconclusive` の返却形式は [reviewer.md](../assets/reviewer.md) を正本とする。未確認事項や実行失敗を成功扱いしない。指摘なしでも確認範囲と根拠を返す。親は返却された対象版が固定版と一致することを照合する。

- 相談依存なら作業を止め、問い・証拠・既知の試行・阻害要因・再開情報を親へ返して実行を終える。相談契約は [escalation.md](../../artifact-workflow/references/escalation.md) に従う。
- 親は全指摘の採否と理由を記録し、必須修正を根拠なく任意提案へ格下げしない。採用した必須修正と完了に必要な未確認事項を解消する。元のタスクIDで worker へ修正を返し、変更後の最新版を影響範囲で独立再レビューして、親がタスク・全体条件を検証する。
- 古い版のレビュー結果で完了にしない。レビュー未実施、入力不足、結論不能なら親が阻害要因を管理し、完了判定を保留する。有効な修正案や新根拠がなく同じ問題が残る場合は再レビューを繰り返さず、親が任意相談または必要なユーザー判断を扱う。

## 実行枠

worker 最大3人、reviewer 最大1人、相談役最大1人を親が管理する。client 枠が共通なら全実行の合計を実際の上限内にする。交代・相談時の停止、枠解放、再開情報は [escalation.md](../../artifact-workflow/references/escalation.md) に従う。
