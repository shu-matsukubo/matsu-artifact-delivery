# 拡張指示の管理

この Skill は登録・更新・一覧の依頼、または会話の内容を今後にも適用したい意向が明確な場合に使う。通常の管理タスクから計画、worker、reviewer、承認ゲートを起動しない。MCP は保存・一覧・検索・取得・更新・削除と revision 管理だけを行い、指示、Skill、依存先、コマンドを実行しない。

方針は Hono API 実装、React 画面実装、社内向け PowerPoint 資料など、利用者が成果物を作る単位でまとめる。横断的な「セキュリティ全般」のように実装対象を特定しない方針や、同一成果物の lint、型検査、実行コマンド、注意を別々にした方針は作らない。登録数に固定上限は設けない。広い既存方針の分割や重複方針の統合は、変更案を示して明示同意を得る。

## 登録

1. 利用者の依頼と指定参照先だけを根拠に、既存一覧を `list_extensions` で調べる。類似候補は `get_extension` で全文を確認し、新規作成より既存方針の更新を優先する。重複・分割・統合の判断が必要なら候補と差分を提示し、明示同意を得る。
2. 利用者の意図を保ち、次の項目へ整理する。保存前に対象方針、変更前後の差分、適用対象を短く提示し、明示同意後に `register_extension` で保存する。
   - 登録フォームの項目と形式は MCP の入力仕様に従う。
   - `type` は `artifact` とし、実装時の指示とレビュー時の遵守確認に同じ内容を使う。
   - `target` と `applicability` は対象成果物と適用条件を示す。
   - `summary` は一覧で選択できる短い説明、`instructions` は利用者が求めた実行指示にする。
   - `dependencies` は必要な Skill、参照先、ツールを示す。実行可否は[実行境界](../../artifact-workflow/references/execution-boundaries.md)に従う。
3. 要求にない手順、コマンド、品質基準、確認事項を補わない。意味や実行影響が変わる解釈が必要な場合は差分を示して同意を得る。
4. 保存成功を確認してから ID・名前・revision を報告する。失敗時は成功扱いせず、今回の会話で成果物作業が依頼されていれば保存失敗と分けて続行する。

既存 ID があれば登録を中止し、上書きしない。更新は現在の全文・revisionと提示済み差分への同意を照合し、`update_extension` を呼ぶ。競合・書込失敗では上書き、自動マージ、無制限再試行をせず失敗を報告する。必要なら利用者から改めて依頼を受ける。

## 一覧・詳細・削除

- 一覧や絞り込みは `list_extensions` を使う。返るのは選択用メタデータであり、全文が必要な場合だけ `get_extension` を使う。
- 詳細、更新、削除の結果は、ID・名前・種別と要点を人が分かる形で示す。
- 利用者が名前で更新・削除を求めた場合は一覧で名前を照合する。対象が一意なら該当 ID の詳細を取得し、内容と操作を示す。複数候補なら ID を特定してもらう。
- 削除は利用者が明示的に求めた対象だけに、現在の `revision` を指定して `delete_extension` を使う。曖昧な一括削除は行わない。

## 失敗時

MCP 接続失敗、破損・不正な保存データ、重複 ID、revision 競合、保存失敗を成功扱いにしない。失敗の種類を説明し、データを空の一覧で置き換えたり、推測で復元・上書きしたりしない。再取得できない場合は状態を伝えて必要な確認を求める。実行可否・依存利用・権限・上位制約は[登録指示と依存先の実行境界](../../artifact-workflow/references/execution-boundaries.md)に従う。登録データの更新は計画セッションの初期化・置換・回収と独立している。
