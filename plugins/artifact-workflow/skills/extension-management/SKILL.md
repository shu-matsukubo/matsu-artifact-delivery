# 拡張指示の管理

この Skill は、利用者が登録管理を依頼したときにだけ使う。成果物の生成・レビュー依頼では起動せず、Workflow が管理 MCP の登録データを選ぶ。MCP は登録指示の保存・一覧・検索・取得だけを行い、生成、レビュー、Skill やコマンドの実行はしない。

## 登録

1. 利用者の依頼と指定参照先だけを根拠に、既存一覧を `list_extensions` で調べる。類似候補は `get_extension` で全文を確認する。
2. 利用者の意図を保ち、次の項目へ整理して `register_extension` で保存する。
   - `id`: 一意で安定した英数字・`.`・`_`・`-` の識別子。
   - `name`: 人が理解できる短い名前。
   - `type`: `generation` または `review`。
   - `target`: 対象となる成果物・作業。
   - `applicability`: 適用する条件。
   - `summary`: 一覧で選択に使える短い説明。
   - `instructions`: 利用者が求めた実行指示。
   - `dependencies`: 任意の Skill、参照先、formatter・lint・静的解析等のコマンド。
3. 要求にない手順、コマンド、品質基準、確認事項を補わない。文章を項目へ配置するだけで意味・実行影響が変わらないなら保存する。意味や実行影響が変わる解釈が必要な場合だけ、差分を示して利用者へ確認する。
4. MCP は依存先やコマンドを実行しない。登録前にも実行しない。保存結果の ID・名前・種別を人が読める形で報告する。

既存 ID があれば登録を中止し、上書きしない。利用者が更新を求めた場合は、現在の全文と変更内容を照合し、意図せぬ変更がないことを確認して現在の `revision` とともに `update_extension` を呼ぶ。競合時は詳細を再取得し、最新内容と意図を照合してから判断する。

## 一覧・詳細・削除

- 一覧や絞り込みは `list_extensions` を使う。返るのは選択用メタデータであり、全文が必要な場合だけ `get_extension` を使う。
- 詳細、更新、削除の結果は、ID・名前・種別と要点を人が分かる形で示す。
- 利用者が名前で更新・削除を求めた場合は一覧で名前を照合する。対象が一意なら該当 ID の詳細を取得し、内容と操作を示す。複数候補なら ID を特定してもらう。
- 削除は利用者が明示的に求めた対象だけに、現在の `revision` を指定して `delete_extension` を使う。曖昧な一括削除は行わない。

## 失敗時

MCP 接続失敗、破損・不正な保存データ、重複 ID、revision 競合、保存失敗を成功扱いにしない。失敗の種類を説明し、データを空の一覧で置き換えたり、推測で復元・上書きしたりしない。再取得できない場合は状態を伝えて必要な確認を求める。参照先を読むことは実行許可にならず、依存の可用性と実行許可を実行環境で確かめる。登録指示は上位 Workflow、承認済み計画、権限・安全制約を上書きしない。依存が利用できない場合は完了条件への影響を確認し、必須条件を満たせない場合は成功扱いしない。登録データの更新は計画セッションの初期化・置換・回収と独立している。
