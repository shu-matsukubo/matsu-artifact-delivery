# 相談役の契約

## 役割

| 役割 | 用途 |
| --- | --- |
| `escalation-advisor` | 限定した論点の設計案比較、根拠・見落としの確認、実行可能な次の一手の助言。通常はこちらを選ぶ。 |
| `escalation-deep-advisor` | 必須条件の矛盾、重大なセキュリティ懸念、広範な不可逆変更、先の助言を検証しても解消しない論点を再検討する。初回から選べる。 |

固定された順序や両者の合議を要求しない。両方とも同じ読み取り専用の境界と入出力契約を使う。モデル名と推論強度は client 固有の役割定義だけで管理する。

## 親が渡す入力

- **依頼の識別**：相談ID、呼び出し元の親識別子、元の担当、今回の明示依頼。親識別子は client のエージェントID・タスクの正規名を使い、取得できなければ呼び出し元の作業IDとその作業内で一意な親ラベルの組を使う。表示名は補助情報とし、ラベルだけで親の権限を判定せず実際の委任関係を確認する。
- **限定した問い**：判断してほしい1つの論点、観測した事実、影響する必須条件。
- **作業範囲**：目的、成果物、完了条件、変更可能な範囲、制約。実装・検証は元の担当が行うこと。
- **根拠**：必要なコード・文書・仕様・ログの参照先と該当箇所、対象バージョン、確認済みの事実、未確認の前提。参照が使えなければ必要な抜粋。
- **試した方法**：候補案、原因仮説、採否、検証の実測結果。再相談なら過去の助言と今回の問い。
- **返却契約と禁止事項**：下記の返却項目、読み取り専用、外部への書き込み禁止、再委任禁止。契約を読める参照先または本文を渡す。

親が記録と起動を担当し、相談役は台帳や報告ファイルを編集しない。検討に不可欠な入力がなければ `input_insufficient` と不足内容を返す。回数・上限・区間IDは本契約の入力要件に含めず、相談役は回数による拒否やリセットを行わない。

## 相談役が返す結果

短い結論と判断に必要な根拠を返す。長い内部の思考過程や逐語的な推論ログは要求・保存しない。

| 項目 | 内容 |
| --- | --- |
| 相談ID・親識別子・役割 | 親の依頼と対応する識別子。受け取った値を返し、別の名前を付け直さない。 |
| 結果の状態 | `advice`（判断材料を返せた）、`input_insufficient`（入力不足）、`inconclusive`（検討したが結論を出せない）、`human_decision_required`（人間だけが決められる事項がある）。 |
| 結論 / finding | 判断した内容。問題なしの場合も確認できた範囲を限定する。 |
| 根拠 | 参照先・箇所・観測事実。根拠からの推測を事実と分ける。 |
| 前提・未確認事項 | 結論が成立する条件、読めなかった資料、検証していない事実、追加で必要な情報。 |
| 推奨対応 | 元の担当が行う次の行動と、その採否を決める検証方法。必要なら候補案と取引条件を示す。 |
| 残るリスク | 推奨案を採用しても残る失敗・影響・不確実性。 |
| 人間判断 | 必要／不要とその理由。必要な場合は判断してほしい事項。 |

`advice` は作業の解決・完了を意味しない。相談役は作業の停止範囲を決めず、次の相談を開始したりユーザーに承認を求めたりしない。

## 親が付ける呼び出しの状態

相談役が起動できない場合も同じ形式で親へ結果を返せるよう、親が次の情報を記録する。

| 項目 | 内容 |
| --- | --- |
| `status` | 取得した相談役の結果の状態。起動前の利用不能は `unavailable`、起動を試した後のエラー・結果未取得は `no_result`。起動前の入力不足は `input_insufficient`。 |
| `attempted` | 起動や追加回答の生成を試したか。事前確認だけなら `false`、実行を試した後は失敗しても `true`。 |
| `execution_state` | `not_started` / `running` / `completed` / `stopped` / `unknown`。起動が拒否され実行されていないと確認できた場合は `not_started`、実行有無を確認できなければ `unknown`。 |
| 実行ID・理由 | 得られた実行ID、役割未登録・環境不備・`capacity` などの理由、エラーや未取得の事実。 |
| 結果の参照先 | 取得できた助言。未取得ならその旨を示す。 |

`status` と実行状態は別に扱う。例えばタイムアウトなら `no_result`、`attempted: true`、`execution_state: running` または `unknown` を返し、親が状態確認を続ける。状態照会や同じ実行の結果回収だけでは、新しい起動試行にしない。

消費回数の計算、上限到達、再相談、自力での継続、部分停止、全体停止は呼び出し元の判断とする。本 Plugin は `limit_reached` のような上限判定を返さない。助言を取得していないのに `advice` や「レビュー済み」としない。
