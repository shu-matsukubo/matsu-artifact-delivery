# 相談役の契約

## 役割

| 役割 | 用途 |
| --- | --- |
| `escalation-advisor` | 限定した論点の設計案比較、根拠・見落としの確認、実行可能な次の一手の助言。通常はこちらを選ぶ。 |
| `escalation-deep-advisor` | 必須条件の矛盾、重大なセキュリティ懸念、広範な不可逆変更、先の助言を検証しても解消しない論点を再検討する。初回から選べる。 |

これは相談の深さを選ぶための役割であり、固定された順序や両者の合議を要求しない。両方とも同じ読み取り専用の境界・入出力契約・共有上限を使う。モデル名と推論強度は client 固有の役割定義だけで管理する。

## 管理者が渡す入力

- **依頼と試行**：作業ID、区間ID、管理者、元の担当、試行ID、確保済みの区間内の使用回数／上限3回。再開した区間なら中断後のユーザーの返答の記録。
- **限定した問い**：判断してほしい1つの論点、該当する発火条件ID、観測した事実、影響する必須条件。
- **作業範囲**：目的、成果物、完了条件、変更可能な範囲、制約。元の作業の実装・検証は元の担当が行うこと。
- **根拠**：必要なコード・文書・仕様・ログの参照先と該当箇所、対象バージョン、確認済みの事実、未確認の前提。参照が使えなければ必要な抜粋。
- **試した方法**：候補案、原因仮説、採否、試行・検証の実測結果。再相談なら過去の助言と今回追加する証拠・問い。
- **返却契約と禁止事項**：下記の返却項目、読み取り専用、外部への書き込み禁止、再委任禁止。共通契約を読める参照先または本文を渡す。

管理者が記録・起動を担当し、相談役は台帳・報告ファイルを編集しない。確保済みの試行情報や検討に不可欠な入力がないときは、推測で補わず `input_insufficient` と必要な情報を返す。相談役自身がユーザーに承認を求めたり、次の相談を開始したりしない。

## 相談役が返す結果

短い結論と判断に必要な根拠を返す。長い内部の思考過程や逐語的な推論ログは要求・保存しない。

| 項目 | 内容 |
| --- | --- |
| 作業ID・区間ID・試行ID・役割 | 管理者の記録と対応する識別子。 |
| 結果の状態 | `advice`（判断材料を返せた）、`input_insufficient`（入力不足）、`inconclusive`（入力を検討したが結論を出せない）、`human_decision_required`（人間だけが決められる事項がある）。 |
| 結論 / finding | 判断した内容。問題なしの場合も確認できた範囲を限定する。 |
| 根拠 | 参照先・箇所・観測事実。根拠からの推測を事実と分ける。 |
| 前提 | 結論が成立する条件。 |
| 未確認事項 | 読めなかった資料、検証していない事実、追加で必要な情報。 |
| 推奨対応 | 元の担当が行う次の行動と、その採否を決める検証方法。必要なら候補案と取引条件を示す。 |
| 残るリスク | 推奨案を採用しても残る失敗・影響・不確実性。 |
| 人間判断 | 必要／不要とその理由。必要な場合は判断してほしい事項。 |

`advice` は作業の解決・完了を意味しない。管理者は元の担当による実装・検証結果を別に記録する。

`unavailable`（役割・モデル・実行環境が使えない）と `no_result`（起動エラー、タイムアウト、応答未取得）は、管理者が起動状態から記録する。相談役の回答を取得できていないのに `advice` や「レビュー済み」としない。`unavailable` でも、実際に起動を試した場合は1回を消費する。
