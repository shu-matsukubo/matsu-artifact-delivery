# 相談役への相談

作業主体を元の担当に残し、明示的に依頼された論点だけについて助言を受ける。特定の Workflow、成果物形式、工程、外部サービスには依存しない。

## 呼び出しと責務の境界

- ユーザーが本 Skill を指定したとき、または呼び出し元の Workflow・親が本 Skill を名前で指定して1件の相談を依頼したときだけ開始する。難所の検出、一覧への掲載、本文の読み込み、資料中での言及だけでは開始しない。
- 現在の作業全体の親だけが相談役を起動する。単独作業では自分が親になる。子ワーカーや途中の親は依頼を最上位の親へ返し、本 Skill や相談役を直接起動しない。
- 本 Skill は累計の回数上限・リセット・自動再相談を持たない。明示的な依頼ごとに相談でき、呼び過ぎの制御、同時起動枠、再試行、停止・再開の判断は呼び出し元の親が管理する。
- 相談役は読み取り専用の手順を守るよう指示する。実装、ファイル更新、外部への書き込み、権限拡大、再委任を行わない。これはプロンプトによる指示で、実行権限を技術的に制限しない。助言の採否と実装・検証は元の担当へ戻す。
- 相談の失敗や利用不能は結果として親へ返す。作業全体の中断や全ワーカーの停止を本 Skill から要求しない。

Codex では `allow_implicit_invocation: true` により通常のモデル向け一覧への公開と暗黙選択を許可する。相談の開始条件は、description と上記の明示依頼の規則で制限する。親は現在のタスクで利用可能として提示された本 Skill の実際のパスから、この本文を読む。client の正式な一覧機能を使う場合も、現在のタスクの設定が反映された一覧に限る。親の応答中に `$expert-escalation` と書くことは読み込み操作の代わりにならない。取得・読み込みだけでは相談役を起動しない。

## 進め方

1. **明示依頼と入力を確認する。** 親が判断してほしい問い、作業範囲、証拠、試した方法をまとめる。子からの依頼だけで起動せず、親が利用を決める。問いの整理に必要なら[相談する論点の例](references/triggers.md)を読む。
2. **呼び出し元の条件を確認する。** [原理原則と呼び出し境界](references/principles.md)に従い、親が自分の回数・同時起動枠の方針を確認する。これらの管理を相談役へ委任しない。
3. **入力を用意する。** [相談役の契約](references/advisor-contract.md)に沿って入力を準備する。相談役は1役に固定し、論点の難しさに応じた役割選択は行わない。
4. **1件を起動して結果を返す。** 親は入力・実行枠を事前確認し、標準 subagent を1件起動する。読み取り専用の手順と契約をプロンプトで渡す。subagent は親のモデルと推論設定を継承するため、親がタスク全体に適した設定を選ぶ。結果に起動試行の有無と実行状態を添え、取得できなければその事実を返す。
5. **親が次の対応を決める。** 親は助言を元の担当へ渡して根拠と必要な実装・検証を確認する。再相談には新たな明示依頼を作る。自力での継続、該当作業だけの停止、全体停止、ユーザーへの確認は、呼び出し元の規則と実際の阻害要因に基づいて親が判断する。

結果の記録には[エスカレーション結果テンプレート](assets/escalation-result-template.md)を使える。相談役の回答を既存のレビュー・完了条件・人間の判断の代わりにしない。
