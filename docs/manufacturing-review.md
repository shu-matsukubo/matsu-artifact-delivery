# 製造・レビュー観点

実装や文書を変更するときに、該当する項目を確認する。

- **責務**: Plugin、Skill、Agent、MCP、各資料が一つの役割に収まり、既存機能と境界が重ならない。
- **規格**: Agent Plugins / Agent Skills の標準で表現できる構成を優先し、独自形式を増やす場合は理由と差分を記録する。
- **実装言語**: 保守するソース・テスト・補助スクリプトは TypeScript とし、生成 JavaScript はソースから再生成する。
- **正本と生成物**: 変更する正本を特定し、生成手順と整合性検証を保つ。生成物だけを手編集しない。
- **契約との整合**: 実装、権限、参照先、文書、テストが実際の責務と規格に一致し、必要な参照が配布物からも解決できる。
- **簡潔さ**: 同じ説明を複数の入口に置かず、詳細は必要な資料へリンクする。

該当しない観点は無理に変更しない。詳細な構成・契約 ID・試験手順は [試験と差分 CI](testing.md) を参照する。
