# 製造・レビュー観点

実装や文書を変更するときは、該当する観点を確認する。

- **責務**: Plugin、Skill、Agent、MCP、各資料がそれぞれ一つの役割を担い、既存機能と境界が重ならない。
- **規格**: Plugin と Skill の構造・実装は[プラグイン仕様](https://agent-plugins.org/)と[スキル仕様](https://agentskills.io/)に従う。標準で表現できない独自形式を導入する場合は、理由と標準との差分を記録する。
- **実装言語**: 人間や AI が保守する実装、テスト、補助スクリプトは TypeScript（`.ts`）を基本とする。生成 JavaScript はソースから再生成する。
- **文書**: 文書・スキル・エージェント向けの説明は日本語で記述する。ファイル名、規格上のキー、固定識別子、コマンド、API 名は原表記を使い、その説明文は日本語にする。通常の文書には現行の仕様・利用方法・方針を記述し、試行履歴、課題対応の経緯、旧仕様との比較を残さない。履歴を記録する文書は除く。過去の制約を前提に「不要」と説明せず、必要な機能・構成・手順を直接記述する。
- **配置**: 利用者向け情報は `README.md`、開発の入口は `AGENTS.md`、開発者向け詳細は `docs/` に置く。資料の配置と参照関係は [Codex 開発ルールの配置と責務](codex-workflows.md) に従う。Skills は概要・制約・フローを入口に記し、詳細を責務別 Reference に置く。Asset は利用役割ごとに所有させ、正本をリンクで示す。
- **開発用 Skills**: 制約の機械保証と自然言語の配置は[Skill 設計方針](../.agents/skills/plugin-skill-authoring/references/design-policy.md)に従う。補助スクリプトは既存コマンドで代替できず、必要性と責務が明確な小規模な状態確認・静的チェック・検証に限る。この制約は配布対象の `plugins/` には適用しない。
- **正本と生成物**: 変更する正本を特定し、生成手順と整合性検証を保つ。生成物だけを手編集しない。
- **契約との整合**: 実装、権限、参照先、文書、テストが実際の責務と規格に一致し、必要な参照が配布物からも解決できる。
- **簡潔さと分割**: 同じ説明を複数の入口で繰り返さない。独立した責務や参照・変更の境界がある場合に分割し、話題や長さだけでは細分化しない。

該当しない観点は無理に変更しない。詳細な構成・契約 ID・試験手順は [試験と差分 CI](testing.md)、配布仕様は[配布と更新](distribution.md)を参照する。
