# Skill 制約の棚卸し

全10 Skill の決定論的制約は既存実装・スキーマ・テストを保証の正本とし、CI で実 Skill ファイルを検査する。自然言語は利用条件、役割、会話判断、停止・継続をモデルへ伝えるために残す。契約テストは必須文言の回帰を検出するもので、モデルが指示に従うこと自体は保証しない。

## 全 Skill 共通

| 制約                                                                                               | 保証と根拠                                                                                                                                                                |
| -------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| frontmatter の name / description、タイトル、概要・制約・フローの順序、Markdown のリンクとアンカー | `scripts/check-skills.ts` が全 Skill を発見し、`validate-skill.ts` と共通 `scripts/markdown.ts` で検査する。正常系・異常系は `DEV-U08` / `DEV-U10`。                      |
| 全 Skill の参照グラフ、欠落 Skill、配布 Plugin の境界逸脱                                          | `checkSkills()` が共通 `walkReferences()` を使い、配布 Skill は各 Plugin をルートにする。欠落・リンク・アンカー・境界の負例は `DEV-U10`。全10件と参照グラフは `DEV-U09`。 |
| 検査の CI 到達                                                                                     | `npm run check` が `check:skills` を実行し、workflow / escalation の Skill 変更で走ることを `CI-U11` が検査する。                                                         |
| 配布 Skill の manifest 登録、metadata とディレクトリ名の一致、配布範囲、README・参照先の実在       | `test/lib/plugin.ts` は共通 `scripts/markdown.ts` の `localLinks`, `walkReferences` を再利用する。Workflow / Escalation 構成 E2E と `PKG-U05` が配布物を検査する。        |
| Skill の適用判断、親子の責務、承認や人間判断、文意                                                 | 契約文テストは文言の回帰のみを検出する。意味判断・実行時の遵守は自然言語として残す。                                                                                      |

Plugin 契約 ID のシナリオ名は [試験と差分 CI](testing.md) に記載する。契約にない文章を機械的に正しいとみなさず、保証範囲の追加・変更時は対応する既存 test を更新する。
