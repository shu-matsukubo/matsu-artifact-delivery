# テスト・検証観点

変更で守る契約を先に特定し、必要な検証を選ぶ。

- **範囲**: 変更したコンポーネントと依存先を対象にし、対象を分類できない場合や共通基盤の変更では全体へ広げる。
- **層**: ロジック・構成契約は単体試験、配布物の参照グラフや実プロセスの接続は E2E で確認する。
- **契約**: 正常系だけでなく、不正入力・欠落・失敗時の扱いを確認する。自然言語の必須指示や参照先は実ファイルを検証する。
- **MCP**: MCP 試験の追加・変更時は単体/E2E の対象登録と、対象一覧の網羅性を確認する。
- **配布**: manifest、配布対象、ローカル参照、生成 bundle の整合を確かめる。リリース前は必要に応じてインストール試験を行う。
- **限界**: 契約文の検査は文言の欠落を検出するもので、自然言語の意味全体や実モデルの遵守を証明しない。

コマンド、対象選択、CI 分類、試験 ID、既存契約の一覧は [試験と差分 CI](testing.md) を参照する。配布検証の手順は[配布と更新](distribution.md)に記載する。
